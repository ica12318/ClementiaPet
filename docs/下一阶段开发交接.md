# 下一阶段开发交接 · 克莱门莎的问候、提醒与对话

**交付目标**是让博士在晚上遇到她时获得一句得体的问候，能按自己的节奏收到喝水邀请，也能主动找她聊，或接着她刚才的话说下去。基线为 2026-11-20 的“悬垂爱心版”。本任务书中的频率、时段和内容数量均为首版建议默认值，集中配置，便于试玩后调整。

## 1. 用一次傍晚相遇验收产品

18:40，博士打开桌宠。首次提示消退、角色空闲后，克莱门莎说：“晚上好，博士。我正给手稿收个尾。您想听听最后一句吗？”博士继续打字，气泡自然消失，编辑器始终有焦点。若博士右键选“接着聊”，才打开对话窗，并显示刚才那句话。博士输入“想听”，克莱门莎读出一句；博士追问“为什么用这个词”，她能接着解释。若博士直接选“聊两句”，即使当天没有出现过问候，也可以自己选话题。

稍后到了喝水时间。克莱门莎说：“我想停笔喝口水。博士，您也歇一口吗？”用户可以忽略，也可以回复“喝过了”或“十分钟后”。这些选择必须改变下一次提醒的时间。

## 2. 角色写作依据

克莱门莎协助罗德岛在阿戈尔和伊比利亚开展合作，能耐心处理会面与措辞。她研究词语，也会与有共同爱好的人聊历史题材小说；“小帮手”是很自然的话题。这给写作者三个落点：斟酌一个词、交换一个看法、为对方留出选择。具体设定查阅游戏档案与语音；下文的对白均为桌宠原创。[干员档案与语音整理](https://prts.wiki/w/克莱门莎) · [明日方舟官方干员展示](https://www.taptap.cn/moment/856123274512302191)

| 写作判断 | 可直接使用的台词 | 应删改的写法与理由 |
| --- | --- | --- |
| 晚间问候简洁，有交谈余地 | “晚上好，博士。要读一页，还是安静待一会儿？” | “怎么又加班到这么晚！”从系统时间推断加班，还带有责备。 |
| 喝水是邀请，回应要尊重选择 | “博士，到了您留给茶歇的时间。喝口水再继续？” | “今天第八杯，必须喝完。”虚构饮水记录，语气也像命令。 |
| 亲近感来自共同兴趣 | “这页我改了三次。博士，您觉得‘抵达’和‘回来’，哪个更像一句问候？” | “博士不陪我，我就不开心。”把普通交谈写成索取安慰。 |
| 形态变化沿用同一人物口吻 | 小蝠鲼悬停时：“我可以在这儿停一会儿。您接着说。” | 每句都加拟声词、海浪比喻或爱心，会让造型取代人物性格。 |

主动气泡写一到两句，只谈当前时段、自己正在做的事或用户明确告诉她的事。避免声称读过打开的文件、知道博士多久没喝水、替游戏角色新增重大经历。每条文案交付时附场景、可用形态、承接话题与人物依据，让内容审阅者能单独判断是否出戏。

## 3. 什么时间说哪句话

| 事件 | 建议触发条件 | 首版内容 |
| --- | --- | --- |
| 晚间问候 | 系统本地时间 18:00 至 22:59，当天第一次满足展示条件。启动与跨入时段均可触发 | 至少 4 句；同一本地日期至多展示一次 |
| 喝水提醒 | 设置中主动开启；默认间隔 60 分钟，可选 30、60、90、120 分钟。首次开启从当前时间开始计算 | 至少 4 句；提供“喝过了”“十分钟后”“关闭提醒” |
| 随机闲谈 | 默认开启；每次重新从 25–45 分钟中抽取一个等待时间，首次运行也等待完整间隔 | 至少 6 句，覆盖措辞、手记、阅读等话题；至少 2 句能接着聊 |
| 用户发起 | 右键角色或托盘选“聊两句”；有待回复话题时另提供“接着聊” | 两种形态均可进入，至少 3 个主题支持连续两轮用户输入 |

**同一时刻只展示一句。** 用户操作和现有反馈优先，主动事件依次选喝水、问候、闲谈。任意两次自动发言至少相隔 5 分钟；喝水的“十分钟后”以用户选择为起点。错过的闲谈直接重新抽时，晚间问候只在当晚有效。内容按类别洗牌，用完再洗，同一类别跨轮也避开上一句。每分钟重新抽概率会造成扎堆，应只在安排下一次时抽样。

**安静时段默认 23:00 至次日 08:00。** 隐藏、锁屏、系统休眠、读手记、聊天、菜单打开、等待单双击裁决、提起、变身、点击文字气泡或爱心正在展示时，暂停主动展示。穿透模式仍允许展示，回复入口始终可从托盘访问。用户自己发起对话不受安静时段限制。隐藏与睡眠期间不累计闲谈时间；恢复后至少留 60 秒缓冲。多个到期的喝水提醒合并为一次。被阻塞时只保留各类到期状态，实际显示成功后才记为已发送。

**喝水回复有明确后果。** “喝过了”从现在起重新计一个完整间隔；“十分钟后”只安排一次延后；“关闭提醒”同步取消待发项并保存开关。用户忽略时从本次展示起算下一个完整间隔。开启、关闭和修改间隔均在设置中即时生效；提醒设置与随机闲谈、晚间问候各自独立。

## 4. 怎样实现双向交谈

首版保持离线运行。采用人工编写的对话节点、快捷回复和本地短文本匹配。用户可自行输入一句话；先在当前节点匹配意图和同义词，再匹配全局意图。支持“先忙”“再见”随时结束；空输入不发送。遇到未覆盖的问题，可以说“这件事我还没想好。我们先谈谈那页手稿，好吗？”，并给出可选话题。开放域自由问答可另立里程碑，首版交付不依赖模型账号。

**对话窗**由用户通过菜单显式打开，采用可聚焦的普通窗口。输入框 Enter 发送，Esc 关闭；同一时间只有一个对话窗，重复打开将已有窗口带到前台。自动冒泡时只缓存话题 ID，保留原文供“接着聊”恢复；默认 10 分钟后过期，新邀请可替换旧邀请。过期后仍可通过“聊两句”选题。气泡本身继续鼠标穿透。关闭或隐藏即结束本次会话，恢复角色此前的形态与活动，聊天内容默认仅保存在本次窗口内存中。

| 话题与起点 | 用户第一轮 → 她的回应 | 用户第二轮 → 她的回应或动作 |
| --- | --- | --- |
| 晚间手稿，“您想听听最后一句吗？” | “想听” → “我写的是‘有人在岸上等她回来’。‘回来’这个词，倒让我改了最久。” | “为什么？” → “‘抵达’只说她到了哪里。‘回来’还说，那里有人认得她。” |
| 喝水邀请 | “等一下” → “好。十分钟后，我再来问您？” | “好” → “就十分钟。您先忙。” 同步安排延后；“不用了”则结束本轮，按常规间隔再提醒 |
| 博士从菜单主动选择“聊聊小说” | “你喜欢哪种结尾？” → “我偏爱留一点余地的结尾。读到最后，还能跟人争论两句。” | “比如呢？” → “比如两位证人各说了一半。您先听谁的，会读出两种故事。” |

快捷回复与自由输入命中同一分支时，回复和设置变更必须一致。已经消费的“十分钟后”等操作不可因双击发送或重新打开窗口执行两次。用户主动选择“喝过了”后，托盘里的旧提醒邀请同时失效。

## 6. 分步交付与验收

1. **先交内容和调度。** 准备上述台词池、三个话题和旧版设置迁移。用假时钟与固定随机种子验证触发、洗牌、跨日与冷却，不让验收者等待真实的一个小时。
2. **再接通互动。** 完成主动气泡、右键／托盘入口、双向对话和喝水操作。先跑通“她先问 → 用户接话”，再跑通“用户先问 → 她接答 → 用户追问”。
3. **最后交 Windows 包。** 用原有构建脚本生成 EXE，运行原桌面回归及下表用例。交付源码、嵌入内容、可运行 EXE、更新后的 README，以及逐项测试结果。记录实际测试环境和未验证项。

| 验收操作 | 可观察结果 |
| --- | --- |
| 把时间从 17:59 推到 18:00，等首次提示结束，再于当晚重启 | 当晚显示一次晚间问候；重启不再问第二遍。次日傍晚又有资格。 |
| 连续抽完一个类别再抽下一轮，在两种形态分别运行 | 本轮无重复，换轮不连说同一句；蝠鲼只使用适合该形态的文字。 |
| 令三个事件同时到期，角色正在被提起；随后松手 | 提起与爱心淡出时无自动文字；恢复后按优先级展示一条，后续遵守冷却。 |
| 喝水提醒选“十分钟后”，推进 9 分 59 秒，再推进 1 秒 | 前者无提醒，后者在允许展示时只出现一次；选“喝过了”后重新计算完整间隔。 |
| 晚间关闭喝水提醒；跨午夜、重启、休眠再恢复 | 开关有效，提醒不会补发；安静时段无自动问候。旧版形态和阅读进度均可还原。 |
| 在编辑器输入时触发主动闲谈，再从托盘“接着聊” | 冒泡保留编辑器焦点；显式打开后才能输入对话。两轮回复承接同一话题，Esc 关闭。 |
| 关闭所有主动发言，在全身穿透模式从托盘选“聊两句” | 用户仍可发起对话。未知输入有自然回退，重复开窗只有一个实例，关闭后恢复活动。 |
| 运行既有桌面回归，人工逐条审阅新增台词 | 单双击、变形、手记、提腰爱心、透明穿透及设置保存通过。每句能说明她为何在此时开口；删除责备、假定监控、强行亲昵和无来源的剧情断言。 |
