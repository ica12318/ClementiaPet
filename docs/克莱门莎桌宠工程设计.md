# 克莱门莎桌宠 · 工程设计与开发交接

版本 1.0 ｜ 首发目标 Windows 11 x64 ｜ 交付给实现、动画与测试 AI

## 1. 首版要交付的体验

用户正在浏览网页。克莱门莎在人形待机时低头翻阅手稿。点她的手，她会抬手致意；点手稿，她会递出一张有标题、正文和署名的纸页。双击身体，手稿合拢，一道水纹掠过，小蝠鲼从同一位置舒展双翼，沿浏览器窗口上方缓缓滑翔。用户仍能滚动页面、选字和打字。再双击小蝠鲼，她收翼落下，恢复人形。

首版采用系统级桌面覆盖层。“页面”指当前前台应用的可见客户区，浏览器、编辑器、PDF 阅读器均可演示。切换浏览器标签时继续在同一窗口巡游；切换应用时更新飞行范围。运行时只需要窗口几何与可见状态，所有动画、台词和文档随包离线提供。

角色取材：克莱门莎与阿戈尔有关，档案提到“双吻前口蝠鲼”、语源考证，以及她对历史题材小说的兴趣。官方展示里，她还邀请博士为打印出来的小帮手起名。本作将这些细节用于造型和互动；可逆变身、巡游路线、下列台词与手记均为本作同人创作。角色参考见[鹰角活动公告](https://ak.hypergryph.com/news/5101.html)、[明日方舟官方展示](https://www.taptap.cn/moment/856123274512302191)和[游戏档案整理](https://prts.wiki/w/克莱门莎)。

## 2. 交互契约

首版同时交付两种文字反馈：一句即逝的**气泡文案**，以及可主动翻阅、关闭和重读的**文档卡**。首次启动仅展示一次提示“点手稿读信，双击变身，右键找我”。所有示例台词均可直接用于首版。

| 操作 | 人形 | 小蝠鲼 |
| --- | --- | --- |
| 单击头部／双翼 | 侧首倾听。“博士，我在听。您可以慢慢说。” | 停住、轻摆被点的一侧翼。“这股水流，往您那边去了。” |
| 单击手部／躯干 | 抬手致意。“这次会面，要从哪件小事谈起？” | 原地绕半圈再悬停。“收到。我会在这一带巡视。” |
| 单击手稿 | 递出纸页并打开文档卡 | 通过右键“读手记”打开同一组文档 |
| 双击任意实体部位 | 合稿、化形、进入巡游 | 收翼、落定、恢复人形 |
| 按住实体并拖动 | 拎起、随指针移动、松开落定 | 暂停航线、随指针移动、松开后重新选线 |
| 右键 | 两种形态共用“变身／还原、读手记、鼠标穿透、隐藏、退出” | 同左 |

**手势裁决。** 按下立即提供轻微姿态反馈，并冻结飞行位移，方便双击移动目标。用系统双击时间和双击矩形判定同一实体上的两次点击，超时才派发单击。移动越过系统拖动阈值后捕获鼠标，取消待发单击及双击。松开或丢失捕获均清理按压状态。两次独立快点若超出双击矩形，按各自命中区处理。热区重叠时手稿优先，其次手／翼、头、躯干。右键直接开菜单。

**反馈节奏。** 每个常用单击热区至少准备两句短文案；轮换时排除上一句。气泡约 3 秒后消退，在屏幕边缘换向；重复单击替换当前气泡。卡片一次只开一张，重复打开时定位到已有卡片。卡片支持键盘翻页、Esc 关闭、鼠标关闭；托盘提供相同命令和“召回到当前屏幕”。穿透模式下通过托盘恢复交互。

## 3. 一份值得点开的手记

首版内置三页，每次点手稿翻到下一篇；卡片显示篇名、页码、正文、“克莱门莎｜同人手记”及前后页按钮。关卡片后恢复之前的待机或巡游，重启保留上次读到的篇目。

| 篇名 | 可直接使用的正文 |
| --- | --- |
| 《“岸”的另一种写法》 | 博士，假如让海里的人给“岸”下定义，您猜他们先画哪一边？我画了潮水退去后还留在石头上的那条细线。您可以在旁边再画一条。 |
| 《会面前五分钟》 | 会面表上空出了五分钟。我原想用来复核措辞，可对面那位研究员也带了同一本小说。等我们争完第三章的结尾，茶刚好凉到能喝。 |
| 《小帮手的名字》 | 小帮手已经绕桌子游了三圈。我叫它回来，它没回头；我试着叫它“逗号”，它倒停在了句子中间。博士，这算它自己选的吗？ |

可选扩展，在首版验收后实现“小帮手命名”。读完第三篇后，在卡片末尾出现“给它取名”。用户确认后，小帮手以独立的小剪影绕人形一周；下次读到这一页，页脚显示“今日随行：〈名字〉”。限 1–12 个可见字符，纯文本渲染，允许改名。小帮手与玩家双击变出的蝠鲼用不同尺寸和轮廓，动作状态互相独立。

## 4. 技术路线与模块边界

采用 C#、.NET 10、Windows Forms。托盘、卡片和设置使用普通控件；精灵由一个小尺寸无边框原生分层窗口绘制。第一阶段先用两张可辨认的占位剪影验证跨进程命中与焦点，再制作正式动画。

| 模块 | 输入 | 输出与职责 |
| --- | --- | --- |
| DesktopHost | 系统鼠标、前台窗口、显示器、托盘命令 | 提供时间、工作区、前台客户区和域事件；管理窗口句柄、鼠标捕获及退出清理 |
| PetController | 域事件、当前状态、单调时钟 | 唯一有权切换形态与行为；产出动作 ID、气泡／卡片请求、位置目标 |
| FlightPlanner | 可飞矩形、当前位置、经过时间 | 返回下一帧中心点、朝向与翼姿；用可注入随机种子和时钟做确定性测试 |
| SpriteRenderer | 动作 ID、播放进度、朝向、DPI | 绘制预乘 alpha 位图，返回当前帧的部位映射和一次性的播放结束事件 |
| ContentStore | 动作、文案、手记清单与用户设置 | 验证资源引用，选取文本，保存阅读进度及偏好 |

**窗口实现。** 精灵窗口使用 WS_EX_LAYERED、WS_EX_TOOLWINDOW、WS_EX_NOACTIVATE，UpdateLayeredWindow 提交逐像素 alpha，SetWindowPos 用置顶及 SWP_NOACTIVATE。WM_MOUSEACTIVATE 返回 MA_NOACTIVATE，保留鼠标消息。alpha 为零的空白让下方应用接收点击；可点窗口内的非零像素均须有默认躯干热区，剔除大片半透明投影。气泡放在独立穿透窗口。用户选择全穿透时给精灵设置 WS_EX_TRANSPARENT；阅读卡是用户主动打开的普通可聚焦窗口。[分层窗口与命中测试](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features) · [鼠标激活规则](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-mouse-input)

**飞行范围。** 进程启用 Per-Monitor V2 DPI 感知。每 200 ms 获取前台 HWND；排除本进程、最小化、隐藏和 cloaked 窗口。将客户区两角转为屏幕物理像素，与目标显示器工作区求交；跨屏时选交集面积最大的一屏。所有边界运算在同一物理像素坐标系完成，包括负坐标；以下设计尺寸以 DIP 表示，在显示器边界处换算一次。

1. 用精灵半宽、半高和 12 DIP 余量向内收缩交集，得到中心点安全区。优先在上方 35% 内巡游。窗口过矮时使用整个安全区；安全区为空则收起航线，停靠该屏工作区角落。桌面或目标关闭时使用工作区。卡片或菜单激活期间冻结目标。
2. 在安全区选左右交替的端点与两枚控制点，用三次贝塞尔曲线连接。所有控制点均在区内；按弧长近似匀速 45–85 DIP/s，靠近端点时减速转向，间隔悬停 1–2 秒。翼尖有缓慢起伏，尾部跟随转向；方向反转时切入转身帧。
3. 目标移动、缩放或切换时作废旧曲线，将中心钳入新安全区，再从该点续飞。跨屏跳变用短淡出／淡入；恢复休眠时丢弃旧帧间隔。拖动结束若在航区外，先停在指针释放处，短淡出后在最近合法点续飞。人形位置只按工作区限制。

## 5. 动作状态与素材契约

形态取 Human、Ray。稳定行为分别为 HumanIdle、RayCruise；短时行为有 React、Morph、Dragging、Reading。菜单开合、穿透和隐藏为独立标志。单线程事件队列串行处理输入、计时与动画回调，动作带递增 playId，已被打断的完成回调直接丢弃。

| 事件 | 接受条件 | 转移与恢复 |
| --- | --- | --- |
| 单击部位 | 待机、巡游或 React | 播放对应 React，结束回到当前形态的稳定行为 |
| 双击／菜单变身 | 待机、巡游或 React | 进入 Morph，播完一次后提交目标形态。期间吞掉重复变身 |
| 开始拖动／释放 | 稳定行为或 React | 中断旧动作进入 Dragging，释放后恢复当前形态 |
| 读手记／关闭 | 稳定行为或 React | 播递稿或悬停，并打开卡片；Reading 期间冻结自动动作；关闭返回稳定行为 |
| 隐藏／召回 | 任意 | 取消捕获与计时器、关闭瞬态窗口，保留最后已提交形态；召回后在当前屏恢复稳定行为 |

**最小动画清单。** 人形制作呼吸、翻稿、侧首、致意、递稿、被拖起、落定；蝠鲼制作扑翼滑翔、单翼回应、绕圈、悬停、转身；两形态各有出入可辨的变形过渡。待机每 18–35 秒可翻稿一次。单次反馈建议 0.5–1.2 秒，变形约 0.7 秒。美术先交一张可辨识人形关键帧、一张展翼关键帧和一张收翼中间帧，确认缩小后的剪影与变身连续性，再补帧。素材使用原创或获准使用的透明 PNG。

**资源组织。** 建议用 assets/actions.json 描述帧序列、帧率、循环、锚点与部位图；content/zh-CN.json 保存气泡和手记。源图用固定画布，每帧同尺寸，帧号从 00 开始；锚点与命中图以源像素记录。移动、缩放及镜像必须对图像、锚点、命中图执行同一变换。下例给出一项非循环动作的数据形状：

```json
{
  "id": "human.greet",
  "frames": ["human/greet/00.png", "human/greet/01.png", "human/greet/02.png"],
  "fps": 6,
  "loop": false,
  "anchorPx": [128, 220],
  "hitMaps": ["human/greet/00.hit.png", "human/greet/01.hit.png", "human/greet/02.hit.png"],
  "bubbleIds": ["greet.meeting", "greet.tea"]
}
```

部位图用无抗锯齿索引色，0 空白、1 身体、2 头、3 手、4 手稿、5 左翼、6 右翼。加载时校验资源存在、帧数、尺寸、FPS、文案 ID 和必需动作。开发包报告具体路径；运行包缺少可选动作时回落到内置静态帧并发出完成事件，避免卡死在 Morph。设置放在 %LOCALAPPDATA%/ClementiaPet/settings.json，带 schemaVersion，以同目录临时文件原子替换；损坏时保留副本，加载默认值。保存形态、位置、缩放、篇目 ID 和穿透偏好。每次启动均先建立托盘入口。

## 6. 交给开发 AI 的实施顺序

| 里程碑 | 本次应交付 | 合入前演示 |
| --- | --- | --- |
| M1 桌面宿主 | 可启动工程、两张占位图、托盘、透明命中、拖放与退出 | 在记事本中持续输入，点击精灵后继续输入；点击剪影旁透明角可直接选字 |
| M2 交互闭环 | 状态机、双击裁决、两套形态、三篇手记和气泡轮换 | 连续双击变身十次；双击手稿只变身，拖动手稿只移动 |
| M3 页面巡游 | 前台客户区定位、曲线、混合 DPI、失效目标回退 | 浏览器切编辑器、移动窗口、最小化、拔副屏后仍可见且可召回 |
| M4 表现与交付 | 完整动画、内容清单、持久化、自包含 win-x64 发布包与启动说明 | 在无开发环境的 Windows 11 机器解压运行，断网完成全部首版交互 |

每次交接附启动命令、修改文件、通过的测试及尚缺素材。先让 M1 跑过真实桌面，再进入 M2；占位图可用于逻辑验收，最终交付须能从轮廓与动作分辨角色及形态。建议标准入口为 dotnet build、dotnet test、dotnet run --project src/ClementiaPet；发布使用 dotnet publish src/ClementiaPet -c Release -r win-x64 --self-contained true。

## 7. 发布验收

- **手势互斥**：向可控时钟注入单击、系统双击间隔内两击、超过间隔两击、按下拖走及捕获丢失。分别断言一次反馈、一次变形、两次反馈、仅拖动、恢复稳定状态；旧动画回调不可逆转新形态。
- **轨迹边界**：固定随机种子，检查 100 条曲线上的采样点及精灵外接矩形。覆盖窄窗、横跨两屏、左侧负坐标、100% 与 150% 缩放切换，断言合法区内无越界、空区域能停靠。
- **真实桌面**：用浏览器滚动、编辑器输入、PDF 选字分别验证透明角与气泡可穿透；点实体有反馈且原应用保留焦点。开启全穿透、隐藏、再从托盘召回；退出后托盘、窗口、计时器均释放。
- **阅读与内容**：每种热区执行两次独立单击，两次文案不同；三篇均可读、翻页、用键盘关闭。关闭卡片后继续原形态，重启可找回阅读进度。缺一帧与损坏配置各测试一次。
- **动画与耗用**：以 30 FPS 为运动渲染目标，印刷式逐帧动画可用较低素材帧率。记录测试机、缩放及 60 秒巡游的帧耗时分布；隐藏时停止绘制和前台窗口轮询。演示视频至少录下“点手稿 → 读一页 → 关闭 → 变身 → 跨应用巡游 → 还原”一整轮。
